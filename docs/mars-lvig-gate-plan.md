# MARS-LVIG: внешний гейт переноса Teach/Repeat

Дата фиксации исходного протокола: 2026-10-16.

Этот документ создан до загрузки полных кадров и до первого запуска алгоритма
на MARS-LVIG. Он отделяет заранее выбранные правила от решений, которые будут
приняты после просмотра development-полёта. Термины раскрыты в
[тезаурусе](glossary.md).

## Практический вопрос

Проверяется перенос уже существующего RGB-конвейера на другую реальную камеру,
высоту и местность:

```text
неизвестный Repeat RGB → десять Teach-кандидатов → геометрическая проверка
                       → подтверждённый эталон или безопасный отказ
```

Набор не заменяет собственный натурный метрический гейт. Он позволяет проверить
поиск места и грубые ложные локализации, но не содержит готовых истинных
координат пользовательских кликов, длин и площадей.

## Почему выбран MARS-LVIG

Авторы публикуют направленные вниз RGB-кадры 2448 × 2048, RTK-позиции и полёты
по одному набору путевых точек с разными скоростями. Для HKairport это 3, 6 и
9 м/с на высоте 80 м. Камера, LiDAR и IMU аппаратно синхронизированы, но рабочий
алгоритм в этом опыте получает только RGB.

Основные источники:

- [официальная страница набора](https://mars.hku.hk/dataset.html);
- [статья MARS-LVIG](https://lawrence-cn.github.io/files/IJRR-LVIG.pdf);
- [официальная папка ROS bag](https://drive.google.com/drive/folders/1aG21le4QZl9LhSLE1O0vuVDQ8YgAwdas?usp=sharing);
- [зафиксированное MCAP-зеркало на Hugging Face](https://huggingface.co/datasets/DapengFeng/MCAP/tree/main/mars_lvig)
  на случай временной квоты официального Google Drive;
- [калибровка камеры из FAST-LIVO2](https://github.com/hku-mars/FAST-LIVO2/blob/main/config/camera_MARS_LVIG.yaml);
- [официальные стартовые смещения последовательностей](https://github.com/hku-mars/FAST-LIVO2/blob/main/config/MARS_LVIG.yaml).

MCAP является сторонней перепаковкой, а не независимым новым набором. Для него
проверяются опубликованные зеркалом размер и SHA-256, а лицензионное решение
остаётся консервативным: CC BY-NC-SA 4.0 с официальной страницы.

## Зафиксированное разделение данных

| Последовательность | Роль | Скорость | Начало маршрута |
|---|---|---:|---:|
| `HKairport01` | Teach | 3 м/с | пропустить первые 75 с |
| `HKairport02` | development Repeat | 6 м/с | пропустить первые 60 с |
| `HKairport03` | held-out Repeat | 9 м/с | пропустить первые 62 с |

Стартовые смещения взяты из конфигурации авторов, а не выбраны по результатам
нашего алгоритма. `HKairport03` нельзя использовать для настройки масштаба,
порогов, числа кандидатов или правил отказа. Если после его просмотра правило
изменится, понадобится новая независимая последовательность.

Суффикс `_GNSS` означает наличие дополнительных сырых спутниковых сообщений.
Для этого опыта они не нужны: обычные HKairport bag уже содержат контрольную
RTK-позицию DJI.

## Подготовка входа

1. Из ROS bag извлекаются только `/left_camera/image/compressed` и
   `/dji_osdk_ros/rtk_position`. Остальные датчики не подаются алгоритму.
2. Временная метка берётся из заголовка сообщения. Время записи bag допускается
   только как явно отмеченный резервный вариант при нулевой метке заголовка.
3. RTK интерполируется на моменты кадров только в оценочном коде. Поиск и
   геометрическая проверка координат не видят.
4. Перед сопоставлением исправляется радиальная дисторсия по опубликованной
   калибровке HKairport. Затем длинная сторона уменьшается до 672 пикселей без
   изменения пропорций. Исходные JPEG сохраняются отдельно без перекодирования.
   SIFT получает этот кадр 672 × 562. Перед DINOv2 выполняется дополнительное
   уменьшение до 336 × 280: обе стороны кратны размеру фрагмента 14 пикселей,
   а отношение сторон 1,2 практически совпадает с исходным и не создаёт
   скрытого растяжения до CLOUD-формата 4:3.
5. Teach и Repeat разреживаются по RTK-траектории с шагом не менее 5 м. Это
   уменьшает почти одинаковые видеодубли; координаты управляют только составом
   экспериментальной выборки, но не ранжированием кандидатов.

Опубликованные параметры pinhole-камеры дают поле зрения примерно 80,6° ×
70,7°. При высоте 80 м идеальный надирный след кадра составляет примерно
135 × 114 м. Поэтому CLOUD-предел 10 м нельзя считать границей отсутствия
перекрытия для MARS-LVIG.

## Разработка на HKairport02

Не замороженные до development-прогона величины:

- абсолютные пороги числа и доли inlier-соответствий;
- минимальное покрытие кадра;
- пороги ошибки проекции и устойчивости гомографии.

Разрешено выбирать их только по `HKairport02`. Итоговые значения и полный
development-результат должны быть записаны в этот документ отдельным коммитом
до первого запуска `HKairport03`.

Не подстраиваются: DINOv2-S/14, VLAD с восемью центрами, Top-10, SIFT, RANSAC,
размер изображения 672 px, шаг ключевых кадров 5 м и random seed 0.

Воспроизводимая команда development-прогона:

    uv run python experiments/feasibility/mars_lvig_end_to_end_gate.py \
        --mode develop \
        --repeat-sequence HKairport02 \
        --output-prefix outputs/mars_lvig/hkairport02_development

### Результат development и заморозка порогов

Результат получен на 353 ключевых кадрах `HKairport02` до загрузки
`HKairport03`:

| Метрика | Значение |
|---|---:|
| близкий Teach в Top-10 | 351/353 = 99,43% |
| принятый ответ до 10 м | 344 |
| принятый ответ в зоне 10–200 м | 6 |
| отказ | 3 |
| обычное принятие дальше 200 м | 0 |
| принятие в трудном отрицательном контроле | 0 из 353 |
| доступность ответа до 200 м | 350/353 = 99,15% |
| медианная дистанция принятого Teach-кадра | 1,93 м |
| 95-й процентиль дистанции | 6,63 м |
| максимальная дистанция | 25,68 м |

Здесь «доступность» означает долю запросов, которым правило выдало не
катастрофический ответ. Она не равна точности измерения точки на земле.

Все 729 заранее объявленных сочетаний порогов повторно оценены по сохранённым
геометрическим признакам, без нового просмотра изображений. Ни одно сочетание
не приняло обычный или контрольный кандидат дальше 200 м. Диапазон доступности
составил от 15,86% до 99,15%; 54 сочетания дали один и тот же лучший набор из
350 решений. Из этой ничьей выбран наиболее строгий вариант:

| Показатель геометрической проверки | Замороженный порог |
|---|---:|
| число согласованных соответствий | не менее 60 |
| их доля среди сопоставлений | не менее 0,50 |
| доля площади кадра с соответствиями | не менее 0,20 |
| 95-й процентиль ошибки проекции | не более 4 px |
| 95-й процентиль сдвига углов при повторной оценке | не более 10 px |
| отношение числа соответствий победителя ко второму кандидату | не менее 1,0 |

Более строгий набор не дал лучшей development-метрики: на этих данных он
выдаёт те же решения, что и 53 других варианта. Его преимущество лишь в более
консервативном поведении между наблюдавшимися примерами; возможная цена —
больше отказов на `HKairport03`.

Порог записан в `FROZEN_THRESHOLDS`, после чего режим `validate`
разблокирован. Решения сохранены в
`outputs/mars_lvig/hkairport02_development_decisions.csv`, а признаки всех
кандидатов — в соседнем файле с суффиксом `_candidates.csv`. Контрольные суммы

## Контрольные зоны

- до 10 м между Repeat и Teach-камерой — строгая близкая окрестность;
- 10–200 м — неопределённая зона возможного перекрытия; она публикуется
  отдельно и не объявляется автоматически ни успехом, ни ошибкой;
- дальше 200 м — консервативная зона грубой ошибки для HKairport.

Предел 200 м больше диагонали идеального надирного следа. Он не доказывает
нулевого перекрытия при любом наклоне, но заметно безопаснее механического
переноса CLOUD-предела 10 м.

Для трудного отрицательного контроля из ранжированного списка удаляются все
Teach-кадры ближе 200 м. Первые десять оставшихся кандидатов проходят то же
геометрическое правило. Алгоритм координат и причины удаления не видит.

## Заранее заданный held-out-гейт

На `HKairport03` одновременно должны выполниться условия:

- не менее 100 Repeat-запросов имеют Teach-кадр в радиусе 10 м;
- такой близкий Teach-кадр присутствует в Top-10 минимум для 90% оцениваемых
  запросов;
- подтверждённый ответ не дальше 200 м получен минимум для 80% всех запросов;
- нет ни одного обычного принятия дальше 200 м;
- сформировано минимум 50 трудных отрицательных случаев;
- среди трудных отрицательных случаев нет ни одного принятия.

Дополнительно публикуются число ответов до 10 м, число ответов в зоне 10–200 м,
отказы, медиана, 95-й процентиль и худшая дистанция. Эти дистанции описывают
положение выбранного Teach-кадра, а не метрическую ошибку точки на земле.

## Результат held-out-проверки

Единственный прогон `HKairport03` выполнен с замороженными выше порогами.
Гейт пройден: одновременно выполнены все шесть условий.

| Условие | Порог | Результат |
|---|---:|---:|
| оцениваемые запросы | ≥ 100 | 354 |
| близкий Teach в Top-10 | ≥ 90% | 345/354 = 97,46% |
| принятый ответ до 200 м | ≥ 80% | 344/354 = 97,18% |
| обычные принятия дальше 200 м | 0 | 0 |
| трудные отрицательные случаи | ≥ 50 | 354 |
| принятые трудные отрицательные кандидаты | 0 | 0 |

Подробное распределение решений:

- 338 ответов находятся не дальше 10 м от Repeat-кадра;
- 6 ответов находятся в неопределённой зоне от 10,11 до 17,33 м;
- 10 запросов завершились безопасным отказом;
- медиана дистанции принятого Teach-кадра равна 2,83 м, 95-й процентиль —
  8,52 м, максимум — 17,33 м.

Разделение этапов показывает основной наблюдавшийся предел. В девяти из десяти
отказов поиск места не поместил ни одного Teach-кадра ближе 10 м в Top-10.
Только для одного запроса близкий кандидат присутствовал в Top-10, но ни один
кандидат не прошёл абсолютные геометрические пороги. Поэтому на этой
последовательности узким местом чаще был поиск кандидатов, а не замороженное
правило геометрического принятия. Это диагностический вывод по одной трассе, а
не доказательство общего превосходства одного этапа.

Воспроизводимая команда:

    uv run python experiments/feasibility/mars_lvig_end_to_end_gate.py \
        --mode validate \
        --repeat-sequence HKairport03 \
        --output-prefix outputs/mars_lvig/hkairport03_held_out

Арифметическая проверка подтвердила 354 строки решений, сумму

Практический вывод ограничен: RGB-конвейер уверенно перенёсся с Teach-полёта
3 м/с на Repeat-полёт 9 м/с над тем же аэродромом. Этот результат не проверяет
точность координат пользовательской точки, другие типы местности, будущую
камеру или повторную съёмку при существенно иных условиях.

## Ограничения вывода

- Нулевое число ошибок на одной последовательности не доказывает нулевую
  вероятность ошибки вне проверенных условий.
- Глобальный затвор MARS-LVIG не воспроизводит построчные искажения возможной
  будущей камеры.
- RTK даёт точную позицию антенны, но не готовую истинную шестимерную позу
  каждого RGB-кадра.
- DJI L1 и Livox делают возможным отдельный будущий 3D-опыт, однако их нельзя
  незаметно включать в этот RGB-гейт.
- Перенос на остров, город и долину проверяется только после заморозки правила
  на HKairport и оформляется как отдельный эксперимент.

Главный смысл: этот гейт способен опровергнуть переносимость визуального поиска,
но даже успешный результат не заменит собственную Teach/Repeat-съёмку и
метрические наземные контрольные точки.
