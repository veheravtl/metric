# Быстрый старт с Blender для синтетической 3D-сцены

Этот документ нужен не для обучения полноценному 3D-моделированию. Его цель —
позволить открыть сгенерированную сцену, понять её структуру, посмотреть через
камеры и заметить грубую ошибку. Термины компьютерного зрения собраны в
[тезаурусе](glossary.md).

## Что установлено

Проект использует Blender 4.5.14 LTS — выпуск с длительной поддержкой. Blender
одновременно играет две роли:

- в пакетном режиме без окна строит сцену и рендерит изображения для агента;
- в обычном графическом режиме служит пользователю просмотрщиком.

Portable-версия лежит в локальном каталоге .tools и не попадает в Git. Скрипт
установки фиксирует адрес официального архива и его SHA-256 — контрольную сумму,
которая обнаруживает повреждённую или подменённую загрузку.

Повторная установка на новой машине:

    ./scripts/install_blender.sh

Проверка версии:

    ./scripts/blender.sh --version

Blender распространяется как свободное программное обеспечение по GNU General
Public License. Сгенерированные изображения и файлы сцены остаются данными
проекта, а не производными программами Blender. Подробности приведены на
[официальной странице лицензии](https://www.blender.org/about/license/).

## Как воспроизвести G0-smoke

Из корня репозитория выполнить:

    uv run python experiments/feasibility/synthetic_3d_smoke.py

Команда читает
experiments/configs/synthetic_3d_g0_smoke.json, запускает Blender в фоне,
создаёт сцену и затем обычным Python проекта анализирует PNG. Успешный запуск
заканчивается значением passed: true.

Основные результаты находятся в outputs/synthetic_3d/g0_smoke:

- scene.blend — сцена для ручного осмотра;
- scene_description.json — точная копия входного описания;
- reference/orthographic_rgb.png — эталонный вид строго сверху;
- teach/teach_000/rgb.png — кадр первичного пролёта;
- repeat/repeat_000/rgb.png — кадр повторного пролёта;
- generation_metadata.json — версия Blender, позы камер и время генерации;
- smoke_report.json — численные проверки изображений.

Каталог outputs исключён из Git: это воспроизводимые производные данные.

## Как открыть сцену

Самая короткая команда:

    ./scripts/open_blender_scene.sh

Другой файл можно передать первым аргументом:

    ./scripts/open_blender_scene.sh /полный/путь/к/scene.blend

После запуска главное окно делится на несколько областей:

- большая центральная область — трёхмерный вид, или 3D Viewport;
- справа сверху — дерево сцены, или Outliner;
- справа снизу — свойства выбранного объекта;
- снизу — временная шкала, которая в G0 пока не используется.

## Минимальная навигация

Ниже описана стандартная раскладка Blender:

- средняя кнопка мыши и движение — вращать вид;
- Shift и средняя кнопка — сдвигать вид;
- колёсико — приближать и отдалять;
- Home — показать всю сцену;
- Numpad 7 — вид сверху;
- Numpad 0 — переключиться на активную камеру;
- F12 — выполнить обычный рендер активной камеры;
- F11 — показать последний рендер и вернуться обратно;
- Esc — остановить текущий рендер.

Если цифрового блока нет, вместо Numpad 0 используется меню
View → Cameras → Active Camera. Официальное руководство также описывает
[просмотр через активную камеру](https://docs.blender.org/manual/en/4.5/editors/3dview/viewport_render.html)
и команды [Render Image и View Render](https://docs.blender.org/manual/en/4.5/interface/window_system/topbar.html).

## Что проверять в сцене

В Outliner находятся смысловые коллекции:

- Ground — земля, дороги и разметка;
- Objects — здания и отдельный цилиндр;
- Control Points — четыре цветные контрольные точки с известными координатами;
- Teach Cameras — камеры первичного пролёта;
- Repeat Cameras — камеры повторного пролёта;
- Truth Helpers — эталонная камера и источник света.

Коллекция — именованная группа объектов. Значок глаза рядом с ней временно
скрывает группу в окне, а значок камеры управляет её участием в рендере.

Для просмотра конкретной камеры:

1. Выбрать teach_000, repeat_000 или reference_000 в Outliner.
2. В меню View → Cameras выбрать Set Active Object as Camera.
3. Нажать Numpad 0 или открыть View → Cameras → Active Camera.

При обычной проверке нужно убедиться, что:

- земля лежит в плоскости XY, а высота идёт по Z;
- камеры находятся над землёй и смотрят на площадку;
- Teach и Repeat похожи, но не совпадают;
- здания имеют заметную высоту и отбрасывают тени;
- эталонная камера показывает всю площадку сверху;
- контрольные точки не спрятаны под поверхностью.

Такой осмотр выявляет грубые ошибки, но не доказывает метрическую точность.

## Где менять сцену

Входное описание находится в
experiments/configs/synthetic_3d_g0_smoke.json. В нём:

- все мировые координаты и размеры заданы в метрах;
- X направлена условно на восток, Y — на север, Z — вверх;
- cameras задаёт положения, цели и параметры камер;
- objects задаёт простые параллелепипеды и цилиндры;
- render задаёт разрешение и движок.

Файл scene.blend является производным. Его можно временно менять для
исследования интерфейса, но такие изменения исчезнут при следующей генерации.
Повторяемое изменение следует вносить в JSON или генератор, затем снова
запускать smoke-тест.

## Что означают четыре метрики

Средняя яркость — средний серый уровень от 0 до 255. Почти ноль обычно означает
чёрный кадр, почти 255 — пересвеченный белый.

Стандартное отклонение яркости показывает разброс светлых и тёмных пикселей.
Малое значение характерно для почти однотонного изображения.

Робастный динамический диапазон — разница между 99-м и 1-м процентилями
яркости. Процентили отбрасывают единичные выбросы, поэтому один белый пиксель
не может выдать пустой кадр за контрастный.

Плотность границ — доля пикселей на резких переходах, найденных детектором
Canny. Она подтверждает наличие структуры, но не говорит, правильна ли эта
структура.

Главный вывод: прохождение этих порогов означает «рендер технически не пуст»,
а не «геометрия верна».

## Если Blender не запускается

1. Повторить ./scripts/install_blender.sh — готовая установка будет только
   проверена, а не скачана заново.
2. Проверить ./scripts/blender.sh --version.
3. Проверить пакетный режим:

       ./scripts/blender.sh --background --factory-startup --python-expr \
           "import bpy; print(bpy.app.version_string)"

4. Если пакетный режим работает, а окно нет, проблема относится к графической
   сессии или драйверу, а не к генератору. Запуск из терминала сохранит
   диагностические сообщения.

Официальное руководство подтверждает, что фоновый режим не требует
графического окна, и предупреждает, что порядок аргументов командной строки
существенен:
[Rendering From The Command Line](https://docs.blender.org/manual/en/4.5/advanced/command_line/render.html).
