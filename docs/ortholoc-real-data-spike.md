# Первый прогон на реальных данных OrthoLoC

## Зачем понадобился новый срез

Плоский PoC использовал кадр, вырезанный из того же ортофото. Он подтвердил
математику, направление преобразований, работу SIFT + RANSAC и метрическую
цепочку, но почти не создавал разрыва между внешним видом запроса и эталона.

OrthoLoC закрывает этот пробел значительно лучше. Его demo-образец содержит:

- реальный UAV-кадр;
- независимое ортографическое изображение DOP;
- DSM — цифровую модель поверхности;
- мировую XYZ-координату видимой поверхности для каждого пикселя запроса;
- метрический масштаб DOP;
- внутренние и внешние параметры камеры.

Источник: [официальный репозиторий OrthoLoC](https://github.com/deepscenario/OrthoLoC),
[публикация NeurIPS 2025](https://papers.neurips.cc/paper_files/paper/2025/hash/2f6a83edafb6b37a80487ce0a6a47e96-Abstract-Datasets_and_Benchmarks_Track.html).
Код и demo-данные распространяются под CC BY-NC-SA 4.0. Внешние NPZ не
коммитятся; URL, атрибуция и SHA-256 зафиксированы в
`data/manifests/ortholoc_demo.json`.

## Воспроизведение

    uv run python scripts/download_ortholoc_demo.py
    uv run python experiments/feasibility/ortholoc_real_data_spike.py

Первый скрипт загружает только два официальных demo-файла общим объёмом около
37 МБ и проверяет их контрольные суммы. Установка тяжёлого пакета OrthoLoC и его
нейросетевых matcher-ов для baseline не требуется.

## Честное разделение поиска и оценки

Функция привязки получает только два RGB-массива: UAV-кадр и DOP. Она не видит
``point_map``, DSM, позу камеры, метрический масштаб и истинные соответствия.
После завершения SIFT + ratio test + RANSAC отдельный оценщик делает следующее:

1. Переводит мировые X/Y каждого пикселя запроса в пиксельные координаты DOP.
2. Выбирает регулярную сетку 41 × 31 точек кадра.
3. Билинейно получает истинное положение каждой валидной точки на DOP.
4. Переносит те же точки найденной гомографией.
5. Считает плановую ошибку в метрах с учётом signed pixel scale DOP.

Билинейная выборка нужна потому, что SIFT возвращает субпиксельные координаты.
Округление до целого пикселя само добавляло бы сантиметровую погрешность.

Дополнительно по плотной истине подбирается **лучшая одна гомография** методом
наименьших квадратов. Она не участвует в локализации и является намеренно
оптимистичной диагностикой: показывает, насколько вообще возможно описать всю
видимую неплоскую сцену единственной плоской матрицей.

## Как читать визуальный отчёт

Для каждого образца создаётся PNG размером 3000 × 1950:

- сверху слева — реальный UAV-кадр, который получает алгоритм;
- сверху по центру — ортофото и три контура;
- оранжевые точки — плотная 3D-истина для границы кадра;
- голубой контур — результат SIFT + RANSAC;
- пурпурный пунктир — лучшая одна гомография, построенная уже по истине;
- сверху справа — DSM с высотой поверхностей;
- снизу слева — SIFT-пары: зелёные inlier и красные отвергнутые RANSAC пары;
- снизу справа — ошибка найденной гомографии по всему UAV-кадру в метрах.

Цвет карты ошибок ограничен значением P95, чтобы единичная вырожденная точка не
сделала остальные различия невидимыми. Максимум всё равно сохраняется в JSON и
CSV.

## Фактические результаты 2026-10-02

### L34_R0057 — сельская/дорожная сцена

- 54 пары прошли ratio test, 50 из них стали RANSAC-inlier;
- покрытие кадра выпуклой оболочкой inlier-точек — 0,516;
- медианная ошибка найденной гомографии — 0,126 м;
- P95 — 0,472 м;
- максимальная ошибка — 0,891 м;
- лучшая одна гомография по плотной истине: median 0,070 м, P95 0,199 м.

Это первый положительный результат на независимом реальном кадре. Он показывает,
что исходный SIFT baseline не ограничен только вырезанием из той же картинки.
Но одна удачная сцена не задаёт ожидаемую вероятность успеха.

### L15_R0175 — городская cross-domain сцена

- 15 пар прошли ratio test, только 5 стали RANSAC-inlier;
- покрытие кадра — 0,078;
- P95 сдвига углов при повторной оценке — 2822 пикселя DOP;
- медианная ошибка найденной гомографии — 54,23 м;
- P95 — 257,47 м;
- лучшая одна гомография по истине: median 2,45 м, P95 8,88 м.

Это опасный ложный успех: функция вернула конечную матрицу, но она не описывает
правильное положение. Пять RANSAC-inlier согласованы друг с другом, однако их
согласие не означает согласия с миром. Уже вычисляемые показатели покрытия и
стабильности резко отличаются от удачной сцены, но численные пороги отказа по
двум просмотренным примерам назначать нельзя.

Даже oracle-гомография городской сцены ошибается на метры. Следовательно, здесь
одновременно проявились две независимые проблемы:

1. SIFT не выдержал визуальный domain gap и нашёл преимущественно неверные пары.
2. Единственная плоская гомография недостаточна для всей 3D-сцены.

## Что доказано и что не доказано

Доказано только существование по крайней мере одного реального случая, где
простая архитектура даёт дециметровую привязку, и одного случая уверенного
провала. Это сохраняет состоятельность идеи проекта, но опровергает более
сильную гипотезу «SIFT + одна H достаточно для произвольного UAV-кадра».

Следующий эксперимент должен расширить real-data выборку до заранее выбранного
небольшого набора разных сцен и высот. До просмотра результатов нужно определить
критерии технического отказа, основанные на числе, распределении и устойчивости
соответствий. После этого можно отдельно проверить современный matcher и
переход от 2D-гомографии к DSM + PnP, не смешивая два изменения в одном опыте.
