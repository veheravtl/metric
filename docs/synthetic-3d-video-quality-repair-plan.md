# G14-C-R: план ремонта учёта раннего безопасного отказа

Первый полный G14-C обработал все 261 физический случай, но формально получил
1265 решений вместо зарегистрированных 1305. В восьми тяжёлых случаях SIFT не
смог построить alignment: один случай потери разрешения и семь случаев blur.
Runner правильно считал их непринятыми, но сохранял пустой список seed-решений.

Исходный опыт остаётся формально невалидным. Его отчёт имеет SHA-256
`7429a33be6180de44f23cb6ab61212e06a5ba796947605d57581980d1d1f728e`.

Repair фиксируется до изменения кода:

1. Если alignment построен, пять stability-решений остаются без изменений.
2. Если alignment не построен, для каждого из пяти заранее заданных seed явно
   записывается решение `gate_accepted=false` с исходной причиной отказа.
3. Такие записи не получают выдуманных quality-метрик и не могут считаться
   ложным принятием.
4. Изображения, уровни факторов, artifact seed, пороги, метрическая истина и
   существующие решения не меняются.
5. Полный G14-C повторяется; ожидается ровно 1305 явных решений.

Критерии валидности и безопасности остаются прежними. Уже увиденное
диагностическое ложное принятие при шуме не исключается и не исправляется этим
ремонтом: изменение касается только восьми случаев, остановившихся до
построения геометрии.
