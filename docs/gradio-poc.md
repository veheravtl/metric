# Локальный интерфейс Gradio для PoC

## Зачем в проекте появился GUI

На этапе проверки реализуемости недостаточно сохранять только числа и матрицы.
Ошибочная гомография иногда имеет правдоподобную среднюю метрику, но визуально
сразу выдаёт себя двойными контурами, смещением перекрёстка или совпадением
только в одной части кадра. Поэтому интерфейс используется как диагностический
инструмент рядом с автоматическими тестами, а не вместо них.

## Что такое Gradio

Gradio — Python-библиотека для построения локальных веб-интерфейсов вокруг
функций обработки данных и моделей машинного обучения. Программа запускает
локальный HTTP-сервер, а пользователь работает с ним через обычный браузер.
Для текущего запуска используется адрес 127.0.0.1, публичная ссылка отключена,
поэтому эталонное изображение не отправляется во внешний сервис.

Основные понятия:

- Blocks описывает компоновку страницы;
- Image, JSON, Button, Slider и другие компоненты отображают данные;
- события click, change и select связывают действия пользователя с функциями
  Python;
- State позволяет хранить состояние отдельной пользовательской сессии;
- Queue управляет последовательностью длительных вычислений.

Gradio не является математическим ядром проекта. Обработчики интерфейса только
вызывают функции из пакета aerial_mapper и отображают возвращённые NumPy-массивы
и словари. Благодаря этому те же функции можно использовать в тестах, пакетной
обработке или будущем Qt-приложении.

## Запуск

Сначала должен существовать локальный эталон:

    uv run python scripts/download_reference.py

Затем запускается интерфейс:

    uv run python apps/poc_web.py

Страница откроется по адресу http://127.0.0.1:7860.

## Что показывает текущая версия

1. Полный эталонный GeoTIFF с истинным и найденным следами камеры.
2. Синтетический прямоугольный кадр размером 1280 на 960 пикселей.
3. Выборку SIFT-соответствий между кадром и полным эталоном.
4. Обратное наложение, построенное по независимо оценённой гомографии.
5. Количество признаков, inlier-точек и ошибки контрольной сетки.
6. Регуляторы поворота участка и силы плоского перспективного перекоса.

В обратном наложении красный канал представляет синтетический кадр, а зелёный
и синий — эталон. Точное совпадение выглядит серым. Ошибка создаёт красные и
бирюзовые двойные контуры.

## Где проходит граница между генератором и алгоритмом

Генератор создаёт кадр и сохраняет истинную матрицу как скрытый правильный
ответ. Функция привязки получает только два массива пикселей: полный эталон и
готовый кадр. Координаты вырезанного участка, истинная матрица и параметры
деформации ей не передаются.

SIFT независимо извлекает локальные признаки из обоих изображений. Точный
brute-force matcher находит по два ближайших дескриптора, ratio test Лоу
отбрасывает неоднозначные пары, а RANSAC оценивает гомографию и помечает
геометрически несогласованные пары как outlier. Только после завершения этого
расчёта отдельный оценщик сравнивает найденную матрицу со скрытой истиной на
регулярной сетке контрольных точек.

Визуализация соответствий намеренно показывает лишь выборку линий, иначе сотни
пар закрыли бы изображения. Числа в диагностической панели относятся ко всем
найденным соответствиям.

После изменения слайдеров нужно нажать кнопку пересчёта. Такой явный запуск
удобен для учебного эксперимента: можно сначала сформулировать ожидание, затем
получить новый результат и сравнить его с предыдущим.

## Граница применимости текущей синтетики

В этой версии весь видимый участок считается единственной плоскостью. Поэтому
одна матрица гомографии описывает созданный кадр, но теперь эта матрица
восстанавливается по пикселям, а не передаётся из генератора в визуализацию.

Слайдер перспективы не создаёт трёхмерную сцену. Он не добавляет высоту крыш и
деревьев, видимые фасады, тени, закрытые объектами участки земли и параллакс.
В настоящем наклонном кадре точки на земле и на крыше принадлежат разным
плоскостям и в общем случае не могут быть одновременно совмещены одной
гомографией. Поэтому успешный результат на этой синтетике является необходимой
проверкой реализации, но не доказательством работоспособности на кадре дрона.

## Что Gradio позволит добавить дальше

- слайдеры размытия и силы дисторсии (поворот и плоский перекос уже добавлены);
- щелчки по изображениям для ручного задания пар соответствующих точек;
- загрузку кадров и видео пользователя;
- таблицу координат и результатов измерений;
- графики ошибки и доли успешных кадров;
- галерею удачных и неудачных экспериментов;
- потоковое отображение кадров;
- сохранение артефактов и параметров запуска;
- простую парольную защиту локального сервера при необходимости.

Baseline следует известной схеме из официальных материалов OpenCV:
[локальные признаки и гомография](https://docs.opencv.org/4.x/d7/dff/tutorial_feature_homography.html)
и [поиск гомографии с RANSAC](https://docs.opencv.org/4.x/d1/de0/tutorial_py_feature_homography.html).

Gradio подходит для экспериментов и демонстрации модели, но не гарантирует, что
останется финальным интерфейсом. Qt стоит рассматривать позднее, если появятся
требования к сложному редактору разметки, высокой частоте показа видео,
настольной упаковке или глубокой интеграции с операционной системой.

Последовательность количественной проверки, включая обязательный 3D-гейт после
плоского PoC, зафиксирована в [плане валидации](validation-plan.md).
